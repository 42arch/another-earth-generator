# 09 · 渲染、交互与统计

[English](./09-rendering-and-interaction.md) | [简体中文](./09-rendering-and-interaction.zh-CN.md)

> 状态：人口、市场、民族、语言、国家与宗教底图，聚落、路线、国界与圣地叠加层，区域检查器及居民统计已实现；文化图层仍为设计草案。

前五阶段已接入[人口密度、市场可达性、民族、语言、国家与宗教底图](../../../src/core/rendering/shared/world-colorizer.ts)、3D／2D 聚落点、道路、航线、国界与圣地，以及区域检查器。路线拾取当前按所经区域定位；实体级高亮、名称标签与筛选器仍待后续阶段。

## 直观理解

用户每次选择一张人文底图，再叠加城市、路线、国界或圣地，便能比较“哪里有人”“谁治理这里”“居民认同什么”。点选城市时看城市，点选空白地表时看区域；3D 与 2D 显示同一个选中对象。

## 接入现有图层体系

[图层注册表](../../../src/core/world/layer-registry.ts)已有 `isBaseMap`、`canOverlay` 与 `human` 类别，人口、市场、民族、语言、国家与宗教底图以及聚落、路线、国界与圣地叠加层已可用。[LayerBar](../../../src/ui/hud/LayerBar.svelte)读取底图和叠加层。后续可新增文化底图和名称叠加层。底图决定主图例，叠加层可以跨自然与人文底图显示。

人文底色从球面区域数据统一生成，再由[地球渲染器](../../../src/core/rendering/globe/renderer.ts)与[地图视图](../../../src/core/rendering/map/view.ts)分别绘制。道路与国界在 2D 投影接缝处裁切；3D 背面不显示标签。城市和其他地名要按缩放级别、等级与碰撞检测控制密度。现有样式中的人文题签类不等于已有完整标签渲染器。

## 拾取与检查器

当前 [WorldEngine](../../../src/core/world/world-engine.ts)与[区域检查器](../../../src/ui/hud/RegionInspector.svelte)已返回人口、聚落、路线、最近市场、民族／语言居民构成、国家／行政归属及主要信仰构成。聚落点优先，路线通过所经区域索引拾取；圣地目前按所在区域查看。后续拾取结果宜升级为带类型的对象。

## 图例、统计与性能

当前[图层统计](../../../src/core/world/layer-statistics.ts)对民族、语言、国家和宗教按居民人数汇总，国家还列出物理面积；其余多数图层仍以单元数为主。人文图例区分人口密度、居民占比、面积与控制强度；宗教份额由居民构成汇总，不能把各地区“主要类别”的面积当成其人口。点击图例项高亮实体与统计筛选仍待实现。

[配置](../../../src/core/simulation/config.ts)把 `baseMap` 与 `overlays` 放在 `appearance`，人口与交通参数放在 `society`，后者参与重新生成与分享链接。民族、语言与宗教目前没有独立参数；后续需扩展实体筛选及缩放级别控制。
