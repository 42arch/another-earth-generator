# M1 — Natural World Genesis 实施计划

> 更新：2026-11-08。本文件保留 M1 后续工作与验收标准，不自动执行实现或授权检查命令。实际状态见 [PROGRESS](PROGRESS.md)，字段见 [数据契约](WORLD_DATA_CONTRACTS.md)，当前 Stage 与 Buffer 边界见 [生成管线](GENERATION_PIPELINE.md)。不再维护小阶段独立记录。

## 1. 当前起点与范围

M0 工程基础与 M1.1 地质/基础地形已实现并完成历史验收。当前工作区按用户要求在 T0 塑形阶段恢复基础水力/冰川侵蚀，TerrainArtifact 为 `terrain-v22`；水力作用统一为参数值的一半，该实现尚未验收。既有 terrain-v20 的固定 Seed、L4/L6/L8、粗糙度、海平面和 L8 缓存预算记录见 [M1.1 验收基准](benchmarks/M1.1B-terrain-v20-acceptance.json)，不代表 terrain-v22 验证通过。

当前 Mesh 支持 L0–L8，参考地质默认 L6；Worker/Controller、区域查询、缓存和调试入口可复用。WorldSnapshot Schema 2、完整校验与最小 JSON 编解码已存在，但没有生产自然快照组装/发布、水文或生态生成器。M1.2 C0 的实现/链路已通过 core/Web 测试、lint、类型检查、构建、真实 Worker 浏览器回归及 3 Seed × L4/L5/L6 基准验收，详见 [当前进度](PROGRESS.md) 和 [C0 验收基准](benchmarks/M1.2-climate-c0-acceptance.json)。按 M1 通用气候形态条件，地形雨影尚缺专项夹具验收；C0 也不代表气候学标定或最终 C1。cartography 尚未提供正式地图系统，最小内容包不等于 M2 内容库。

迁移以 `docs/old-src` 的 feat-society 为基线，保持只读。算法变化需版本和固定 Seed 对照；不为匹配示例创建空模块，不提前实现 M2 文明、M3 正式地图、M4 浏览器项目管理或 M5+ 动态框架。

## 2. 实施顺序与每段交付

| 范围 | 输入与输出 | 进入后续前的条件 |
| --- | --- | --- |
| M1.1 历史验收 | 当前地质/T0 → 可复验基线 | terrain-v20 通过固定 Seed、字段单位/海陆、缓存、Worker 与基本形态检查；当前含基础侵蚀的 terrain-v22 待验收 |
| M1.2 实现/链路验收通过 | T0 → 初步月气候 C0、分类 | 12 月、月年聚合、季节响应、面积投影、Worker 链路与固定 Seed 多分辨率基准通过；地形雨影专项证据待补，不含全球气候学标定 |
| M1.3 初步水文 | T0/C0 → 径流与排水 H0、冰雪 I0 | 水量账本、出口与辅助面含义明确 |
| 后续气候驱动侵蚀（暂缓） | T0/C0/H0/I0 → 追加侵蚀地形 | 本轮明确不实现；未来需定义与 T0 基础侵蚀的分工 |
| 最终气候水文 | T1 → C1/H1、河流/流域/基础湖泊 | 无环、总量与引用有效，不发布旧轮次状态 |

| M1.5 | 五类自然状态 → 完整无文明快照 | 完整校验、原子发布、只读查询与档案往返 |
| M1.6 | 完整链路 → 回归与性能证据 | 验收项有实际结果，未运行项明确 |

上表为概念依赖，不强制建立同名/同数量 Stage。阶段必须声明实际直接依赖，T0/T1 和 C0/H0/C1/H1 使用明确的身份，禁止循环依赖。每次聚焦一个可验收切片，完成核心、Pipeline、Worker、查询/显示和相应文档；不一次性迁移整套自然模型。

实施位置：核心 Stage 在 `packages/world-core/src/generation`，领域算法在 `src/nature`，快照/校验在 `src/world`；内容在 world-data；Worker、Controller、调试 UI 在 Web。跨包仅用 exports，核心不得依赖 UI、Three.js 或浏览器全局。

## 3. M1.2：季节环流与月度气候

参考旧版季节风、洋流代理、月度 forcing、温度、降水、输出投影和 Köppen 分类。

实施顺序：

1. 初步 C0 从含基础水力/冰川侵蚀的 T0 构建气候表面，使用面积加权聚合；本轮不执行气候驱动追加侵蚀。
2. 迁移季节 forcing 与表面响应，保持职责分离。
3. 迁移月温、月降水求解，先保留旧迭代，再依据对照优化重复计算。
4. 实现气候输出投影及总量验证。
5. 接入气候分类和调试月份切换。

必须处理的迁移差异：

- 当前契约是 **12 个等时长年内分箱**；旧版使用非闰年日历及 `MONTH_DAYS`，不能直接沿用。
- 统一各分箱时长、季节相位、蒸发/融雪计算及年统计；改变旧结果时记录版本。
- 年降水为月总量之和；年均温按分箱时长加权。
- 当前快照要求两个长度为 `12N` 的 Float32 字段。M1 网格上限已扩至 L8；高等级的快照内存需求仍需评估，不提前实现惰性快照系统。
- 旧投影源索引使用 `Uint16Array`。明确上限并拒绝越界，或有需求时改为足够容量的索引。
- 海陆混合、参考格无采样区域及降水投影修正均需测试。

模型明确定位为 `EarthlikeClimateModel`。对尚无合理模型支持的行星参数组合给出显式限制，不静默忽略或截断倾角等输入。

## 4. M1.3：径流、侵蚀、河流与静态湖泊

当前 T0 已含不读取气候的基础水力/冰川侵蚀。M1.3 后续先从此 T0 和初步气候建立 H0 径流/排水及冰雪 I0；依据降雨的追加侵蚀暂不实现。最终气候水文与河湖事实仍需按后续阶段完成，不能将 H0 或代理路由当作最终河网。

**M1.3A 实施顺序：**

1. 从月气候计算年径流，保留可解释的融雪和蒸发近似。
2. 迁移 Priority Flood、下游关系和拓扑排序。
3. 使用实际区域面积累计水量。
4. 建立基础流域、河流路径、稳定 ID 和河网连接。
5. 提供面积、径流、流量、级序及出口查询。

单位必须统一：

```text
区域年产流体积 m³/年
  = annualRunoffMm × areaKm2 × 1000

年平均流量 m³/s
  = 年产流体积 / (orbitalPeriodDays × 86400)
```

旧版固定地球半径不能继续作为任意世界的流量换算依据。

无海洋出口时必须产生显式内流汇点；下游为邻接区域或合法出口，不得形成环。

旧版“运行两年后使用第二年”不能自动证明积雪稳态。记录所选统计年的降水、蒸发、径流及储水变化，避免把积雪增加当成水量损失。

**M1.3B 实施顺序：**

1. 从地形和盆地识别基础静态湖盆。
2. 定义湖泊 ID、盆地引用、区域范围、面积、静态水位及出入口。
3. 区分有出口湖泊与内流湖泊。
4. 将湖泊接入区域查询、调试显示和生态输入。

明确湖泊覆盖与海陆掩码的关系：海陆掩码继续表达地形相对海平面；内陆水体通过独立湖泊归属表达，不能通过地图颜色反推。

路由填洼面不等于湖面。湖泊水位及形成条件须有明确模型依据；不实施逐月水库、水坝或完整动态湖泊平衡。

## 5. M1.4：生态与自然覆盖

参考旧版 Köppen、`biome-classifier.ts` 和生物群系定义。

实施顺序：

1. 明确气候类型、生物群系、土地覆盖三套分类及关系。
2. 迁移月气候序列分类。
3. 根据海洋、湖泊、气候及地形生成自然覆盖。
4. 按实际需要提供基础生态适宜性，明确单位或无量纲范围。
5. 提供区域年度气候、生态分类和解释因素查询。

必须满足：

- 分类 ID 与索引表一致，覆盖所有区域。
- 潜在生物群系和实际覆盖分别保存。
- 无文明世界不得生成农田、城市等人为覆盖。
- 海洋、淡水、冰雪、陆地分类关系明确。
- 月年统计复用同一实现，避免生态与气候各算一套。
- 土壤或农业指数只有在本阶段具有明确模型和消费者时增加；资源分布与文明适宜性扩展留给 M2。

## 6. M1.5：完整快照、Schema 与只读查询

全部自然阶段具备真实结果后，再实施完整发布。

实施顺序：

1. 从产物组装五类自然状态。
2. 创建空文明实体、空人口分组和全零区域人口。
3. 记录完整生成配置、内容版本、全部 Stage 版本与签名。
4. 完整校验候选快照。
5. 通过受控所有者一次切换当前快照。
6. 对外暴露只读字段、区域和自然实体查询。
7. 使用现有档案编解码验证完整自然世界往返。

快照身份、名称、创建时间由调用者提供，不进入随机身份和自然阶段缓存签名。

当前 Schema 2 缺少河流、流域、湖泊等完整事实契约。实现时统一设计最小扩展：

- 必填结构或持久化语义发生不兼容变化时提升 Schema 版本。
- 同步更新校验、档案恢复、测试和契约文档。
- 明确旧 Schema 的迁移或拒绝策略；无法从旧档案恢复的新事实不得伪造。
- 档案格式版本与世界 Schema 版本分别管理。

查询对象不得暴露权威 TypedArray 或底层 Buffer。不要将整个 `WorldSnapshot` 交给 Svelte 或制图层。

## 7. Worker、调试入口与失败恢复

复用现有 Controller/Runtime，新增自然任务时保留 Mesh 调试链路兼容性。

协议需要明确任务类型、requestId、生成来源及结果种类，区分：

- 自然阶段调试产物。
- 已确认完整世界。
- 显示数据及查询响应。

运行时要求：

- 进度覆盖所有实际执行阶段，不再假设只有 Mesh。
- 保留硬取消；同步计算期间不能宣称可协作中断。
- 错误包含 Stage ID 和可读原因。
- 新请求替代旧请求后，忽略旧结果和旧查询响应。
- 生成、校验、传输或显示准备失败时，保留最后有效世界。
- 硬取消重建 Worker 后，明确最后有效世界由谁保留、如何恢复查询；不能只有旧画面仍在而事实已丢失。

当前调试入口为 `/mesh-debug`，优先扩展现有链路；是否拆分新入口按实际交互需求决定。提供板块、高程、海陆、月气候、河流/流域/湖泊、生态及区域检查。

颜色、月份、线框、相机变化只更新显示，不触发自然生成。

## 8. 确定性、缓存与内存边界

- 新自然 Stage 使用现有阶段随机流及稳定 `fork`；不得直接使用 `Math.random()`、时间或不可追踪的局部随机种子。
- Mesh 保持已有随机兼容策略。
- 旧算法改用阶段随机流导致结果变化时，建立 M1 新基线并说明原因，不承诺与旧版逐字节一致。
- 参考映射、板块拓扑、候选大陆、地形和气候按实际读取参数失效。
- Stage 输出归 Pipeline/Cache 所有，下游不得原地修改。
- Worker 仅 Transfer 独立副本或明确转移所有权的显示数据。
- 不为每次月份切换复制整份全年气候。
- LRU 缓存预算不等于整个进程内存上限；Pipeline 执行期间仍持有的产物、传输副本、显示数组与 GPU 数据均需计量。
- 只保存有用途的诊断字段；不要无限保留所有中间数组。

## 9. 测试矩阵与质量基准

| 类别 | 必须验证的行为 |
| --- | --- |
| 正常生成 | 固定 Seed 完成全部自然链，字段类型、长度、单位和引用合法 |
| 确定性 | 冷缓存、命中缓存、强制重算产生一致领域结果；排除时间和任务 ID |
| 参考映射 | 源/目标身份正确、索引有效、换网格重建 |
| 地质地形 | 板块归属、候选与最终大陆区别、高程有限、海陆完全一致 |
| 气候 | 12 月合法、月年聚合一致、季节反转、地形雨影及投影总量 |
| 水文 | 下游邻接、无环、出口/内流合法、汇流和储水账本一致 |
| 湖泊生态 | 湖泊引用与水位有效，覆盖分类和水体关系一致 |
| 缓存 | 改地形只影响必要下游；改气候不重算地质；改显示不生成 |
| 失败恢复 | 阶段失败、校验失败、取消、传输异常均保留有效世界 |
| 跨模块 | 真实 Worker、区域查询、显示切换、档案往返 |
| 回归 | 原有 Mesh 数学、网格 Worker 和调试入口不退化 |

建立固定测试配置，至少包含超大陆、群岛、低起伏三类；在 L4/L5/L6 验证跨尺度行为，L7 用于高规模集成与性能采样。原型是本阶段待建立的配置，不能描述为现有功能。

极端场景通过小型合成夹具覆盖：全海、无海洋出口、平坦面、闭合盆地、零降水、持续积雪、投影零总量和非法输入。

统计容差须根据浮点精度、算法或旧基线确定并记录，不得为使测试通过随意放宽。视觉截图用于补充形态验收，不能代替领域不变量。

## 10. 验证命令与性能记录

以下为已核实存在的脚本示例。**列出命令不代表获得运行授权**；执行 Agent 必须遵循 `AGENTS.md`，用户明确授权后再运行。

```bash
pnpm --filter @another-earth/world-core test
```


现有 `bench:generation` 仅覆盖 Mesh Pipeline；`bench:geology` 和 `bench:terrain` 已存在，但仍不代表完整自然链。未来新增阶段须补相应基准，原始记录统一保留在 docs/benchmarks。

性能记录至少包含：

- Seed、完整配置、网格规模、算法版本、机器及运行环境。
- 冷启动、缓存命中和局部参数变化。

- 产物、缓存、传输和显示数据字节数。

区分数组字节统计、JS 堆采样和 GPU 估计，未测峰值明确写未测。不得用未经实测的秒数或帧率作为完成结论。

## 11. 完成标准与范围限制

M1 完成须同时满足：

1. 真实自然 Stage 串联，不依赖 Mock 或快照测试样例。
2. 板块、地形、气候、水文、生态都有有效字段和可解释来源。
3. 河流、流域与基础静态湖泊能够查询。
4. 完整无文明快照通过领域校验后原子发布。
5. 相同输入在同版本内可复现，变化均有版本记录。
6. 显示变化不修改事实、不触发生成。
7. 取消及失败保留有效世界，查询与画面一致。
8. 完整自然世界通过现有 JSON 档案往返验证。
9. 关键测试、浏览器链路和性能记录具有实际结果；未运行项明确列出，验收保持待验证。
10. 每个子阶段完成代码修改后同步更新进度及相关契约文档。

本阶段不实现初始文明、矿产资源分布、正式 Atlas/六套风格、IndexedDB/OPFS 项目管理、动态文明、编辑器、历史分支、通用大气数值模型或完整板块动力学。

## 12. 执行方式与最终报告

每次执行选定一个子阶段，按以下顺序推进：

```text
审查现状
→ 定义本次契约
→ 迁移核心算法
→ 接入 Pipeline/Worker/调试入口
→ 编写针对性测试
→ 按授权验证
→ 更新进度与契约文档
→ 汇报交付
```

最终报告必须包含：

- 本次子阶段及实际完成范围。
- 主要文件、公开接口、Schema 和兼容性变化。
- 旧算法保留、修正及偏离原因。
- 固定 Seed 对照、实际运行的检查及结果。
- 未运行检查、已知限制和真实阻碍。
- 已更新的进度文档及下一子阶段入口。

不修改旧归档源码，不覆盖用户改动，不自动 Git commit/push。

**执行 Agent 应先审查真实代码后直接实施选定子阶段，不停在规划；遇到无法通过源码、文档和合理工程判断解决的真实阻碍时才询问。**
