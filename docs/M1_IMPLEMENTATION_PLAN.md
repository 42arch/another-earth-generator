## 3. M1.2：季节环流与月度气候

参考旧版季节风、洋流代理、月度 forcing、温度、降水、输出投影和 Köppen 分类。

实施顺序：

1. 初步 C0 从含基础水力/冰川侵蚀的 T0 构建气候表面，使用面积加权聚合；本轮不执行气候驱动追加侵蚀。
2. 迁移季节 forcing 与表面响应，保持职责分离。
3. 迁移月温、月降水求解，先保留旧迭代，再依据对照优化重复计算。
4. 实现气候输出投影及总量验证。
5. 接入气候分类和调试月份切换。

必须处理的迁移差异：

- 当前契约是 **12 个等时长年内分箱**；旧版使用非闰年日历及 `MONTH_DAYS`，不能直接沿用。
- 统一各分箱时长、季节相位、蒸发/融雪计算及年统计；改变旧结果时记录版本。
- 年降水为月总量之和；年均温按分箱时长加权。
- 当前快照要求两个长度为 `12N` 的 Float32 字段。M1 网格上限已扩至 L8；高等级的快照内存需求仍需评估，不提前实现惰性快照系统。
- 旧投影源索引使用 `Uint16Array`。明确上限并拒绝越界，或有需求时改为足够容量的索引。
- 海陆混合、参考格无采样区域及降水投影修正均需测试。

模型明确定位为 `EarthlikeClimateModel`。对尚无合理模型支持的行星参数组合给出显式限制，不静默忽略或截断倾角等输入。

## 4. M1.3：径流、侵蚀、河流与静态湖泊

当前 T0 已含不读取气候的基础水力/冰川侵蚀。M1.3A 已实现 I0 雪水储量/融雪、H0 月水量代理、Priority Flood、流域与阈值河段，并贯通 Worker 和调试页面；Core/Web 自动化、类型/lint/build 与 3 Seed × L4/L5/L6 基准通过。可见 Chrome 页面完成 L4/L6 真实 Worker 生成、区域查询和 H0-only 缓存失效检查；Playwright 自动化因本机 Chrome headless 进程 SIGABRT 未能启动。T0 v24 相同矩阵中未发现低于清理门槛的封闭水体，水体连通分量为 1–3。依据降雨的追加侵蚀暂不实现。最终气候水文与湖泊事实仍需按后续阶段完成，不能将 H0 或代理路由当作最终河网。

**M1.3A 实施顺序：**

1. 从月气候计算年径流，保留可解释的融雪和蒸发近似。
2. 迁移 Priority Flood、下游关系和拓扑排序。
3. 使用实际区域面积累计水量。
4. 建立基础流域、河流路径、稳定 ID 和河网连接。
5. 提供面积、径流、流量、级序及出口查询。

本轮实现覆盖上述五项：`cryosphere-i0-v1` 与当前 `hydrology-h0-v2` Stage 已注册；Worker/Controller 返回并校验产物；`/mesh-debug` 加入积雪、径流、河网、流域专题与区域水量查询。初始实现实测见 [M1.3A 基准](benchmarks/M1.3A-hydrology-acceptance.json)，后续密度校准见 [河网密度基准](benchmarks/M1.3A-river-density-calibration.json)。`hydrology-h0-v2` 将动态汇水阈值从 8×提升到 16×平均 Mesh 面积，并用 Strahler 级序降低低级支流的显示对比度；L6 三 Seed 河道区域数比 v1 减少 39–44%。粗网格 L4 更稀，需按实际显示尺度进一步调参。Playwright headless E2E 因浏览器启动失败未通过；真实 Chrome 页面已手动确认 Worker 生成、查询和缓存局部失效。

雨雪分配、融雪和蒸散为显式配置的温度指数近似，I0 只模拟一个公转周期的积雪水当量，不建模多年冰川体积。当前河流汇水阈值采用 `max(configuredMinimumKm2, 16 × meanMeshAreaKm2)` 并要求正累计流量；L6 三个 Seed 生成 912–1,138 个河道区域、221–245 个河段。河网密度改善不代表全球水文标定。

单位必须统一：

```text
区域年产流体积 m³/年
  = annualRunoffMm × areaKm2 × 1000

年平均流量 m³/s
  = 年产流体积 / (orbitalPeriodDays × 86400)
```

旧版固定地球半径不能继续作为任意世界的流量换算依据。

无海洋出口时必须产生显式内流汇点；下游为邻接区域或合法出口，不得形成环。

旧版“运行两年后使用第二年”不能自动证明积雪稳态。记录所选统计年的降水、蒸发、径流及储水变化，避免把积雪增加当成水量损失。

**M1.3B 实施内容与验收：**

新增 `static-lakes-l1-v4`，依赖 Mesh、T0 和 H0。算法从 `filledElevationKm > terrain.elevationKm` 的陆地区域提取连通洼地；只保留至少包含两个 Mesh 区域的湖泊组件，按区域数而非固定面积过滤单网格水面。水位为洼地成员的最大填洼高程，溢流区域来自 H0 向湖外路由的边界。湖泊 ID 由 Mesh ID 与最小成员区域组成；记录成员区域、面积、静态水位、H0 流域 ID、溢流区和 H0 下游区。`lakeIndex` 对非湖泊区域为 -1。

Worker/Controller 已传输和验证 LakeArtifact，`/mesh-debug` 增加静态湖泊专题、湖泊统计和区域详情。Core 合成测试覆盖封闭洼地、单格过滤、平地/海洋排除、内流终止盆地、稳定 ID、面积和非法数据。v4 的 3 Seed × L4/L5/L6 基准完成 9/9，湖泊数分别为 L4 0–2、L5 3–7、L6 33–39；L8 Seed 42 可见 Worker 生成 1,063 个湖泊，归档见 [M1.3B 静态湖泊基准](benchmarks/M1.3B-static-lakes.json)。Stage 冷运行时间包含完整地形/气候/水文链路，不应解释成 L1 单独耗时。

湖泊覆盖与海陆掩码分离：海陆掩码继续表达地形相对海平面；湖泊通过独立 `lakeIndex` 表达，不由地图颜色反推。L1 先作为 GenerationArtifact 生成，再由 M1.5 装配进 Schema 3；E0 不读取 L1。

静态水位是 Priority Flood 溢流几何代理，不代表水量平衡。当前 v4 按成员网格数过滤单格洼地；v4 数量与确定性已完成固定 Seed 验收。部分多格洼地呈狭长河谷/泛滥平原形态，当前没有经领域依据校准的形状阈值，因此 L1 表达静态潜在积水地形，而不是完整真实湖泊分布。首轮基准若用 T0 的四个 L5 区域清理门槛，L6 九个样本均无湖泊。当前 `endorheic` 沿用 H0 终止流域语义，现有含海洋样本均为开口湖；没有海洋出口的合成场景验证内流标签。该实现未识别海洋行星上的气候性内流湖，不做逐月水库、水坝或完整动态湖泊平衡。

## 5. M1.4：生态与自然覆盖

参考旧版 Köppen、`biome-classifier.ts` 和生物群系定义。

实施顺序：

1. 明确气候类型、生物群系、土地覆盖三套分类及关系。
2. 迁移月气候序列分类。
3. 根据海陆掩码、气候及地形生成生物群系与自然覆盖；河流、湖泊作为独立水文实体，不进入分类输入或掩码。
4. 按实际需要提供基础生态适宜性，明确单位或无量纲范围。
5. 提供区域年度气候、生态分类和解释因素查询。

必须满足：

- 分类 ID 与索引表一致，覆盖所有区域。
- 潜在生物群系和实际覆盖分别保存。
- 无文明世界不得生成农田、城市等人为覆盖。
- 海洋由海陆掩码独立编码；所有陆地区域按气候与地形分类，河网/湖泊不覆盖群系或自然覆盖类别。
- 月年统计复用同一实现，避免生态与气候各算一套。
- 土壤或农业指数只有在本阶段具有明确模型和消费者时增加；资源分布与文明适宜性扩展留给 M2。

**2026-11-12 本轮 M1.4 验收结果**：`ecology-e0-v3` 从 C0/T0 生成类别索引、干旱指数和生长季箱数；所有陆地网格均参与分类，包括 H0/L1 标记的河道/湖泊区域。E0 的 Stage 依赖仅为 Mesh、T0、C0；水文参数不进入 E0 签名，河网/湖泊在显示与契约中保持独立。核对时修复了 v2 误用 Z 轴纬度的分类错误。旧版固定 Seed 同输入分类器回放见[历史对照](benchmarks/M1.4-E0-legacy-comparison.json)，其 T0/C0 是 v24/v2 输入；当前 v25/v16/v3 的合成夹具、四 Seed 面积/纬度/连片诊断、同输入旧分类器回放、Core/Web 定向检查和 Chrome Worker 回归见 [E0 收尾记录](benchmarks/M1.4-E0-closeout.md)。本轮 E0 分类和展示链路按初步模型范围验收；它单独生成时仍是中间产物，M1.5 完整自然链可将其纳入快照，不声称已有逐月土壤/多年冰川模型。

## 7. Worker、调试入口与失败恢复

复用现有 Controller/Runtime，新增自然任务时保留 Mesh 调试链路兼容性。

协议需要明确任务类型、requestId、生成来源及结果种类，区分：

- 自然阶段调试产物。
- 已确认完整世界。
- 显示数据及查询响应。

运行时要求：

- 进度覆盖所有实际执行阶段，不再假设只有 Mesh。
- 保留硬取消；同步计算期间不能宣称可协作中断。
- 错误包含 Stage ID 和可读原因。
- 新请求替代旧请求后，忽略旧结果和旧查询响应。
- 生成、校验、传输或显示准备失败时，保留最后有效世界。
- 硬取消重建 Worker 后，明确最后有效世界由谁保留、如何恢复查询；不能只有旧画面仍在而事实已丢失。

当前调试入口为 `/mesh-debug`，优先扩展现有链路；是否拆分新入口按实际交互需求决定。提供板块、高程、海陆、月气候、河流/流域/湖泊、生态及区域检查。

颜色、月份、线框、相机变化只更新显示，不触发自然生成。

## 8. 确定性、缓存与内存边界

- 新自然 Stage 使用现有阶段随机流及稳定 `fork`；不得直接使用 `Math.random()`、时间或不可追踪的局部随机种子。
- Mesh 保持已有随机兼容策略。
- 旧算法改用阶段随机流导致结果变化时，建立 M1 新基线并说明原因，不承诺与旧版逐字节一致。
- 参考映射、板块拓扑、候选大陆、地形和气候按实际读取参数失效。
- Stage 输出归 Pipeline/Cache 所有，下游不得原地修改。
- Worker 仅 Transfer 独立副本或明确转移所有权的显示数据。
- 不为每次月份切换复制整份全年气候。
- LRU 缓存预算不等于整个进程内存上限；Pipeline 执行期间仍持有的产物、传输副本、显示数组与 GPU 数据均需计量。
- 只保存有用途的诊断字段；不要无限保留所有中间数组。

## 9. 测试矩阵与质量基准

| 类别 | 必须验证的行为 |
| --- | --- |
| 正常生成 | 固定 Seed 完成全部自然链，字段类型、长度、单位和引用合法 |
| 确定性 | 冷缓存、命中缓存、强制重算产生一致领域结果；排除时间和任务 ID |
| 参考映射 | 源/目标身份正确、索引有效、换网格重建 |
| 地质地形 | 板块归属、候选与最终大陆区别、高程有限、海陆完全一致 |
| 气候 | 12 月合法、月年聚合一致、季节反转、地形雨影及投影总量 |
| 水文 | 下游邻接、无环、出口/内流合法、汇流和储水账本一致 |
| 生态水文边界 | H0/L1 改变不改变 E0 分类；湖泊/河流作为独立水文专题表达 |
| 缓存 | 改地形只影响必要下游；改气候不重算地质；改显示不生成 |
| 失败恢复 | 阶段失败、校验失败、取消、传输异常均保留有效世界 |
| 跨模块 | 真实 Worker、区域查询、显示切换、档案往返 |
| 回归 | 原有 Mesh 数学、网格 Worker 和调试入口不退化 |

建立固定测试配置，至少包含超大陆、群岛、低起伏三类；在 L4/L5/L6 验证跨尺度行为，L7 用于高规模集成与性能采样。原型是本阶段待建立的配置，不能描述为现有功能。

极端场景通过小型合成夹具覆盖：全海、无海洋出口、平坦面、闭合盆地、零降水、持续积雪、投影零总量和非法输入。

统计容差须根据浮点精度、算法或旧基线确定并记录，不得为使测试通过随意放宽。视觉截图用于补充形态验收，不能代替领域不变量。

## 11. 完成标准与范围限制

M1 完成须同时满足：

1. 真实自然 Stage 串联，不依赖 Mock 或快照测试样例。
2. 板块、地形、气候、水文、生态都有有效字段和可解释来源。
3. 河流、流域与基础静态湖泊能够查询。
4. 完整无文明快照通过领域校验后原子发布。
5. 相同输入在同版本内可复现，变化均有版本记录。
6. 显示变化不修改事实、不触发生成。
7. 取消及失败保留有效世界，查询与画面一致。
8. 完整自然世界通过现有 JSON 档案往返验证。
9. 关键测试、浏览器链路和性能记录具有实际结果；未运行项明确列出，验收保持待验证。
10. 每个子阶段完成代码修改后同步更新进度及相关契约文档。

本阶段不实现初始文明、矿产资源分布、正式 Atlas/六套风格、IndexedDB/OPFS 项目管理、动态文明、编辑器、历史分支、通用大气数值模型或完整板块动力学。
