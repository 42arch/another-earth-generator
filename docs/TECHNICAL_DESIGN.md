# Another Earth — 技术设计

> 更新：2026-11-23。本文记录当前有效的架构边界与设计决策，不复述逐阶段实现日志。产品规则见 [PRD](PRD.md)，实现状态见 [PROGRESS](PROGRESS.md)，历史设计快照见 [TECHNICAL_DESIGN_REFERENCE.md](TECHNICAL_DESIGN_REFERENCE.md)。

## 架构边界

仓库使用 Bun Workspace，按数据、领域、制图和应用编排划分 Package：

| Package | 所有权与职责 | 依赖边界 |
| --- | --- | --- |
| `@another-earth/world-data` | 内容定义、内容包、命名风格、解析和校验 | 不依赖其他业务 Package、UI、Three.js 或 DOM。 |
| `@another-earth/world-core` | 生成算法、领域规则、`WorldSnapshot` 和只读世界查询 | 不依赖 `world-data`、`cartography`、UI、DOM 或 Worker 全局 API；内容通过调用方提供的视图与 `ContentPort` 注入。 |
| `@another-earth/cartography` | 地图数据源、样式、图层、2D/3D 渲染和拾取 | 只读消费 `world-core` 查询契约，不写回世界事实。 |
| `apps/web` | UI、Worker 生命周期、内容组装、浏览器存储及导入导出流程 | 通过 Package exports 编排其他包，不直接修改核心数组。 |

不为尚无实际消费者的 M2+ 能力建立空框架或额外 Package。跨包只使用公开 exports，避免循环依赖。

## 数据与生成边界

- `ContentDefinition` 是候选内容；`GenerationArtifact` 是阶段产物；`WorldSnapshot` 是通过完整领域校验后发布的权威事实；`MapStyle` / `ViewState` 是显示状态。
- `world-core` 的 Stage 显式声明依赖、算法版本及读取的配置/内容。相同 Seed、输入和版本应可复现；显示状态不进入生成签名。
- 完整自然世界先组装候选快照，再完整校验并原子发布。失败、取消或传输错误保留最后有效世界。
- 已发布 TypedArray 由核心所有者管理。消费者通过只读查询读取；变更生成新候选并整体替换，不原地改写已发布数组。
- Worker 转移独立 Buffer；阶段缓存保留自己的数组，不复用已转移的存储。

精确字段、单位、ID、内容哈希、快照校验和归档格式见 [世界数据契约](WORLD_DATA_CONTRACTS.md)；Stage DAG、签名、缓存与 Worker Buffer 规则见 [生成管线](GENERATION_PIPELINE.md)。

## 当前实现范围

当前工作区已实现自然与 M2 初始文明生成及 Schema 11 发布、`WorldMapReader`、3D Globe、2D Atlas、多投影、地图样式与图层、Worker 编排和区域查询。当前具体能力、验证结论与延期事项以 [PROGRESS](PROGRESS.md) 为准。历史算法沿革、目标设计草图及过往逐轮决策仅供追溯，收录于 [技术设计参考快照](TECHNICAL_DESIGN_REFERENCE.md)；制图引擎细节见 [Cartography-System-Design.md](Cartography-System-Design.md)。

尚未实现的主要里程碑：

- **M4**：浏览器项目保存、恢复与完整世界档案导入导出。
- **M5+**：动态文明、完整编辑器、历史与分支；当前只保留必要的数据边界。

## 已定决策与仍有限制

M2 初始人口的权威值仍按区域实际面积（km²）与承载密度相乘。聚落和政体的社会尺度以旧 L6 类地球默认生成的物理面积为校准基线，约 12,453 km²/参考格；输出 Mesh 只决定表示精度。`population-settlements-v5` 由选址分决定迁入比例和陆地搜索距离，从附近区域向聚落所在格转移人口，但每个供体格子至少保留 44%，保持人口总量与快照的区域归属契约，也不再把城市周围抽成无人区。文化和已建成的交通网不参与该评分。交通与文化传播的基准行进速度固定在该参考尺度对应的旧默认值。它们是兼容旧量级的校准选择，不代表历史人口密度或城市腹地的实测值。自然输入的网格差异和低分辨率的亚格信息缺失仍可能改变文明结果；当前已完成同 Seed L6/L7/L8 三次冷启动实测；只验证当前配置，不代表任意参数或浏览器全链路内存上限。

默认定居背景以 1850–1900 年技术条件为参照。`habitability-v4` 将温度/淡水/地形形成的环境上限，与农业及渔业供给、矿产/能源机会和通达潜力区分计算，再生成近代定居适宜度与承载密度；林木可提供有限燃料替代。矿产与能源只取已保存矿点，供给和资源机会按物理距离及地形阻力沿陆地衰减，保证地图查询可由同一快照输入复算。海岸不再直接增加淡水、荒漠容忍度或人口承载量；港口使用淡水、岸坡和海岸邻居的遮蔽代理。聚落选址读取综合定居分，不再重复叠加沿海和资源奖励。当前预设只提供静态参数情景，没有动态时代切换、铁路/产业演化、跨海供粮或真实贸易流量，也未建立粮食总供需守恒；矿种工艺和开采条件尚未细分。参数及公式见 [生成管线](GENERATION_PIPELINE.md)，承载密度的全局尺度已按约 1900 年人口密度校准，三 Seed L5 拟合与独立 L6 验证见 [CIV-01 基准](benchmarks/CIV-01-calibration.md)；其余权重不视为历史拟合。

当前 `polities-religions-v15` / `peoples-cultures-v4` 保持“自然与社会能力 → 城镇特征 → 国家特征 → 领土 → 政体原型”的单向管线；宗教在领土划界前形成。CIV-03 用确切国家数（整数 1–200、默认 60）替换原数量倍率，并新增面积差异。Web 使用单个步长为 1 的滑杆，数量不随 Seed 抽取。直接以选定整数确定总预算，按人口优先覆盖可达连通片区，剩余首都采用有选址权重的最远点填充，不再因固定间距不足而少建国家。孤岛与大陆共用预算，数量优先于自动本土建国；无预算且不可跨海的地区可以无主，符合 PRD 的非全覆盖规则。无人口世界保留空文明；有人口但候选不足则明确失败，不发布缩水结果。Schema 为 11、分享为 v15，拒绝旧 Schema 1–10 和分享 v14 及更早，不迁移。

面积差异由最终领土分布验收：可达片区内先保留每国首都格面积，剩余物理陆地面积按 `rank^(-2*variation)` 份额作为目标，名次由稳定国家 ID 随机流与特征基础速率共同确定。0 为片区内近均衡目标，1 为逆平方梯度。领土采用每国独立的成本前沿，按已占面积/目标面积调度尚可扩张的国家，再沿该国最低成本前沿扩张；不同国家的文化/宗教/地形系数不会共用一条区域最短距离状态，土地邻接扩张不穿过其他国家已占土地，显式交通捷径仍可连接分离领土。现有可用交通路线可连接陆块，零航海不读海路捷径；政治特征继续影响扩张方向与面积名次倾向，但不再直接决定全世界面积比例。近海和远洋投送只补无主地、不增国。面积不含湖面/海面；首都位置、独立片区、格网、前沿阻塞和整岛投送都可能使目标份额无法兑现，未实现全局最优面积求解或边界再平衡。

三个 Seed/L6 共 15 组生产内容对照验证数量、人口守恒、缓存、面积差异趋势和强制重算；结果见 [CIV-03](benchmarks/CIV-03-polity-layout.md)。这不代表任意参数均严格单调、差异 0 全球等面积或 L7/L8 性能已复验。算法版本为 v12，宗教/制度随机流沿用已有 v8 身份，数量和面积名次使用独立 fork。只改数量或面积差异仅重算政体宗教阶段。

小面积已统一为目录特征 `small-area`，属于新增的领土维度 `territory`，以 `sizeClasses: ["city-state"]` 声明面积类别条件。内置自由领地、酋长领、自治公社和城邦通过 `requiredTraits` 引用它；可选 `allowedSizeClasses` 仍供其他内容使用，内置不重复设置。`polities-religions-v15` 保持先划界后选政体，按实际陆地面积归类，移除单聚落豁免；小面积门槛沿用 3 个参考面积（约 3.74 万 km²），不含海面和湖面。超限领土匹配其他合格原型，不反向拆国或改变请求数量。发布时重算面积和人口份额，拒绝靠标签绕过硬约束；没有合格候选时失败。该内容更新与算法、验证范围见 [CIV-04](benchmarks/CIV-04-polity-size.md)，不承诺四类政体的出现配额。

国家特征目录与政体匹配关系由 `world-data` 拥有：独立 `polity-traits.json` 复用原生内容包结构，由内置加载器计算 `contentHash`，采用短且语言无关的特征 ID（独立于 `ContentId` 命名空间）、维度及双语翻译键。政体候选通过显式包依赖解析 `requiredTraits` 和 `traitAffinities`；偏好条目支持全部特征匹配、排除特征、可选规模条件与按序相乘的正权重。核心经调用方注入结构化视图，负责既有 15 种制度/经济特征的形成/扩张、小面积领土特征派生和通用条件匹配，不直接加载 JSON，也不把任意新增 ID 自动解释为新算法能力。神权国要求 `theocratic`；没有可选政体时阶段失败并沿用既有发布保护。`polities-religions-v9` 固定沿用 v8 随机流，但内容签名和候选约束变化可能改变生成结果，未做固定 Seed 新旧对照。城镇特征无独立内容配置消费者，保留在核心和 Web 翻译中。特征不构成动态时代演化，制度/经济特征仍在扩张前固定；领土特征只在划界后按实际面积派生，不反向影响本轮扩张。当前总计 4 维 16 种特征，每国生成 2–4 项，Web 复用目录翻译显示“小面积”徽章。

权力维度沿用 v11 引入的规则，由当前 `polities-religions-v15` 计算条件支持度并使用 `rng.fork(power-structure:capitalId)` 作稳定加权选择，零分候选禁用，不设世界级配额。v10 将首都占所有腹地人口的比例解释为集中度、以商业/生产比值饱和后抑制集权，并采用最高分必选，实测导致默认世界几乎全部分权；现已改为首都与最强地方中心的相对规模、商业超过生产的正差，取消商业对集权的普遍惩罚。文化组成的 `1−Σshare²`、实际坡度/通行阻力保留为条件信号；游牧另须本地牧业评分领先其他主要生产方式。制度是创世时在条件约束下形成的差异，无法由经济地理唯一推断。保留全局能力门控，不实现制度历史演化；权力之外的随机流仍沿用 v8。v11 的四 Seed L6 历史验证及剩余限制见 [特征分布对照](benchmarks/CIV-02-trait-distribution.md)，不视为历史比例校准。

内置政体包 1.4.0 将通用形态与特殊形态的基础权重分级，补齐王朝贵族与君主形态的匹配；公民议政不再作为王朝制君主国的惩罚条件，王国也不要求必须具备王朝贵族特征。政体形态和单一制度特征不作一一绑定。所有变化配置在双语 JSON 中，核心选择公式、Schema 11 和分享 v15 保持不变，无世界级形态配额或历史比例拟合。14 组固定输入对照保持人口/领土/首都/国家特征一致；Web 默认王国与王朝称号更加常见，分组君主总数并非每个 Seed 都增加。权重、完整分布及兼容边界见 [CIV-05](benchmarks/CIV-05-polity-weights.md)。

`PolitiesReligionsExtraContext.onPowerEvaluated` 提供冻结的逐国评分/输入诊断副本；不保存到快照、不进入缓存签名。生产 Stage 默认不启用该回调。基准从相同上游产物重放末阶段并对照已通过完整校验的政体、聚落和领土，确保诊断未改变结果。

CIV-01 A 批只将农业生产、工业利用、陆运与航海四项能力参数化，默认倍率均为 1；B 批再接入聚居倾向、国家数量倾向与文化多样性，并将旧 `polityCohesion` 替换为行政整合能力。参数在 Pipeline 签名前统一解析，保存有效数值和嵌套副本；地图派生查询从已保存配置读取能力。农业倍率改变单位农业潜力可支持的人口，工业零值保留普通矿业，陆运改变供给/资源陆地衰减范围。实际交通保持参考行程预算固定，只调整旅行速度，避免预算随速度缩放导致效果抵消；航海零值不生成海路，不改变港口地理或近岸领土政策。当时 Schema 为 7、分享链接为 v12；无旧版迁移或旧算法回放框架。C 批增加四份社会背景预设（Web 拥有完整参数表，核心只读取数值），保存和分享不增加预设 ID；后续重调后预设仅管理能力与聚落/政体格局，切换与匹配保留独立轴 `enabled`、`populationScale` 与 `culturalDiversity`，默认“近代工业商贸”将 `urbanConcentration` 提至 0.65、`administrativeCapacity` 提至 0.75（四个 1× 生产/运输能力及 22/7 承载密度基线不变，分享链接升至 v13）。

历史 B 批将国家数量与治理职责分离（数量倍率已由 CIV-03 替换）：首都目标和间距只读 `polityDensity`，采用旧默认凝聚度 0.6 的数量/间距作为 1× 基线；行政能力影响异文化与海路的相对代价，不对所有距离统一缩放，也不重新引入陆地扩张截止。宗教起源间距保持基线，避免调国家数量时连带改变宗教起源选址。文化多样性调整起源目标与间距，但不按“发展阶段”强行减少文化。聚居参数改变募集强度和物理搜索范围，不改变初始人口抽样或聚落候选排名，迁入仍守恒、供体仍保留至少 44%。这三项格局参数及行政能力都不参与宜居性缓存；只调整国家数量/行政时只重算政体宗教。C 批四种预设不构成线性文明等级；文化多样性保持独立，城邦情景可比区域王国更聚居、更擅长航海。预设选择不自动启动生成。

## 验收原则

生成结果变化须记录对应 Stage 版本、原因和可复现证据。性能结论必须来自明确配置与实测，不以规划规模、历史耗时或截图代替基准。历史验证只适用于其注明的代码版本和范围，不自动覆盖当前改动。

当架构或公开契约发生变化时更新本文及相应契约；普通实现细节和局部 UI 调整不更新本文。
