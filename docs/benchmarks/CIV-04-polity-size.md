## 当前：小面积作为特征

“小面积”统一进入 `polity-traits.json`，定义为 `small-area`，新增第 4 维 `territory`，条件为 `sizeClasses: ["city-state"]`。沿用 37,356.41 km² 的实际陆地面积门槛；符合条件的国家在划界后、匹配政体前获得该特征，不占原权力/治理/经济三维的槽位，也不反向参与已完成的领土扩张。总目录 16 项，每国生成 2–4 项。Web 复用目录翻译显示“小面积”徽章。

内置自由领地、酋长领、自治公社和城邦改为 `requiredTraits: ["small-area"]`，删除其重复的 `allowedSizeClasses` 配置；可选通用规模字段仍保留给其他内容。`requiredTraits` 为硬资格，`traitAffinities` 为乘权偏好，后者不能保证大国绝不匹配小政体。当前目标仍是严格小面积。特征只约束划界后的政体选型，不主动缩小领土或改变请求国家数。

发布/归档完整校验从权威归属重算面积与人口份额，拒绝缺失或伪造的领土特征及规模。Schema 升至 11，拒绝旧 1–10；分享参数未改，仍为 v15。旧世界须重新生成，旧内容包按清单版本与哈希核对，不迁移。

复现：`bun run --cwd apps/web benchmarks/polity-size-constraints.ts trait`。三 Seed/L6/1、60、200 国共 9 组均通过完整快照校验，国家数准确、四类政体面积超限为零；所有国家的 `small-area` 存在与否均和实际面积一致，四类小政体全部满足必需特征。数据见 [v15 特征复验](CIV-04-polity-size-trait-L6.json)。

## 原因与规则

原规则只降低大国抽中城邦、公社、酋长领的概率，仍然允许抽中；自由领地没有大国排除条件。另一个问题是 `sCount <= 1` 会把只有一座聚落的巨大领土也归为 `city-state`。固定 Seed 1024、默认 60 国时，自由领地达到约 187 万 km²，自治公社甚至约 1902 万 km²。

两份 `polities-zh-cn.json` / `polities-en.json` 为 `free-territory`、`chiefdom`、`commune`、`city-state` 显式声明：

```json
"allowedSizeClasses": ["city-state"]
```

这是硬候选条件，先于特征加权；亲族、分权、山地或其他强偏好不能绕过。该可选字段由 `world-data` 拥有，省略表示不限制，显式值须为非空、去重的合法规模数组。解析、内容包往返、双语目录、内容哈希及文明缓存签名均包含它。

沿用现有物理面积门槛：`city-state` 为不超过 3 个参考支撑面积，即 **37,356.41 km²**，不含海面与湖面。移除聚落数的特殊豁免，稀疏大国按实际面积归类。其他规模门槛保持现状：不足 8 个参考面积为 regional，8 个及以上为 kingdom；18 个及以上且占已归属人口至少 25% 为 empire。

保持“领土形成 → 选择符合特征与规模的政体”的顺序。大领土选择其他合格政体，不通过缩地、拆国或追加国家改变用户选定的国家数；不保证四种小政体都出现。若定制内容没有合格候选，明确失败。发布与档案完整校验还根据权威归属重算面积和人口份额，不能通过伪造 `sizeClass` 绕过约束。结构模式只检查声明规模，不替代完整发布校验。

内容更新仍使共用 `civilization-content` 的文明阶段缓存失效，自然与资源可复用；仅算法版本变化使末阶段失效。旧快照不自动重写名称或政体；需重新生成采用新结果。旧内容清单必须匹配其版本与哈希，不迁移内容包。
